## Evidence boundaries

The active-restart failure is a client defect, not a Nova terminal-evidence failure. The startup subscription adopted the original session, and its live session-completed event arrived while reporting was held. After replay durably confirmed the report and callback, the replay path omitted dispatching the returned session-completed acknowledgment. The active-session guard therefore correctly prevented a blanket return to FREE. Sol's correction processes exact stored acknowledgment/readback only after durable callback acknowledgment, includes the crash window before session cleanup, and defers next-task requests until connection reconciliation completes. Physical and manual holds and unrelated sessions remain protected. Nova remained frozen; every final case was executed with the corrected client and explicit source attribution. The failed database and export are retained unchanged.

The initial disconnect and immediate-ack exports retained an earlier first-order snapshot even though the later READY assertion had passed. Those original exports remain unchanged. `supplement-disconnect-01` (2026-09-22 21:07:49 UTC) and `supplement-ack-immediate-01` (21:08:06 UTC) record fresh read-only API responses against each retained database, both original and follow-up orders READY, API ownership, and successful owned-process cleanup. They are supplemental observations, not additional executed cases. The fixture now stores the fresh final readbacks after the READY gate.

Each final run captured actual loaded source paths/hashes, selected manifest, seven fixture source copies/hashes, configuration, API PID/start ticks/database ownership and fake-provider evidence. Acceptance checked exact order/session/task/execution correlation across provider, Nova, client and the platform fields it exposes, and compared total start requests with unique accepted identities. The platform API does not expose the controller execution ID; that binding is retained in Nova and client evidence.

For negative controls, unchanged journal hashes refer to the immediate pre/post refused-CLI snapshots. In readiness-false, a later legitimate completion callback updates the journal while the device remains PAUSED and the next order queued; the whole later session is not byte-static.

Positive runs waited for both durable stores and callbacks to settle and measured device FREE. ## Remaining limits

This validates one bridge and queue/journal pair per isolated run, real local API/Socket.IO/ROS transport, and an explicitly fake controller. It does not establish hardware safety, successful physical picking, concurrent-writer correctness or power-loss durability. Server-side non-idempotent completion replay, cancellation inventory reconciliation, and mixed-success order settlement remain open platform issues. Operator resolution records a local audited disposition; it does not repair cancelled-order accounting or fabricate platform acknowledgment. Original product checkouts and historical evidence are preserved; the Nova migration was committed after validation as `39c6aff523e95bc03a1db10bb854aec8746d0df9` without changing the tested source hashes. The original manifest retains its capture-time uncommitted state.
